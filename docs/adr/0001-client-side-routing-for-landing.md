# Клиентский роутинг для главной и страницы записи

Приложение было одностраничной заглушкой без навигации, но со сценарием «гость записывается на встречу» — а значит, главной и странице записи нужны собственные URL. Мы решили добавить `react-router-dom`: `/` — главная (лендинг о проекте), `/book` — заглушка страницы записи, неизвестные маршруты редиректятся на `/`. Это делает точку роста для будущей функции бронирования явной: логика записи появится по адресу `/book`, а не «где-то на той же странице».

## Considered Options

- **Одностраничник с якорями** (отклонён): «страница записи» как отдельная сущность не появилась бы вовсе, CTA вёл бы на секцию той же страницы. Для сервиса бронирования, где запись — главный сценарий, это лишает навигацию явной структуры.

## Consequences

- `/book` — честная заглушка без формы выбора слота; реальное бронирование — отдельная задача, и она должна жить по этому маршруту.
- Новая зависимость `react-router-dom`; все будущие страницы добавляются как маршруты, а не как новые секции лендинга.
