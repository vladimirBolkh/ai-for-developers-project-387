# 02: Тема встречи при записи и на подтверждении

Parent: #19

**What to build:** Гость при записи указывает обязательную однострочную тему, видит её на экране успешной записи, а API сохраняет обрезанный снимок темы во Встрече. Пустая/пробельная тема и тема длиннее 200 символов отклоняются с `400` до создания встречи. При конфликте слота тема не теряется. Владелец пока не обязан видеть тему — это следующий срез, но контракт и сохранённые данные уже готовы.

**Blocked by:** 01 — Глоссарий «Тема встречи» (термин должен появиться до или вместе с реализацией).

**Status:** ready-for-agent

- [ ] В TypeSpec обязательное строковое поле `topic` добавлено в `BookingRequest` и `Meeting`; артефакты клиента и сервера пересозданы через `npm run spec:all`, сгенерированный код вручную не правился.
- [ ] Сервер обрезает тему по краям, отклоняет пустую/из одних пробелов и длиннее 200 символов после обрезки с `400`; сообщение явно говорит о теме.
- [ ] Созданная Встреча хранит обрезанную тему как снимок и не зависит от последующих изменений или удаления Типа события.
- [ ] На странице записи в форме Гостя есть обязательное однострочное поле «Тема встречи» с ограничением 200 символов рядом с именем.
- [ ] Пустая/пробельная тема не отправляется: показывается локальная понятная ошибка, запрос в API не уходит.
- [ ] В `BookingRequest.topic` уходит обрезанная тема; email остаётся необязательным и не влияет на возможность указать тему.
- [ ] При занятом слоте (`409`) показывается прежнее сообщение, а введённая тема не теряется.
- [ ] Экран «Вы записаны» показывает тему встречи.
- [ ] Тесты доменной логики покрывают сохранение снимка, обрезку и отказ для пустой/пробельной/слишком длинной темы; тесты страницы записи покрывают обязательность поля, локальную ошибку, обрезанное значение в запросе и показ темы на подтверждении.
- [ ] Фикстуры `Meeting` и `BookingRequest` в тестах обновлены под обязательное поле; `lint` → `format:check` → `test` → `build` зелёные.
